# TCGA multimodal embedding preparation — reproducibility starter

This directory is intended for the **course project's data-preparation PR**.
The report and UNI2-h scripts are independently usable; the presence of a script
does **not** imply that all histology projects have been processed.
The PyHealth library's dataset/model PR is a separate contribution; the team's
`FULLPIPELINE_README.md` explicitly describes reproduction scripts as **local
tools, not part of the upstream PyHealth PR**. Confirm the destination repository
and branch with the team before committing.

## Scope and verified result (2026-11-13)

- Source: Song et al., *Multimodal Cancer Modeling in the Age of Foundation Model Embeddings*;
  public researchers' repo: <https://github.com/StevenSong/multimodal-cancer-modeling>.
- Inputs: `data/summarized_reports.csv` (`patient_filename,text`) and
  `results/split_cases.csv` (`case_id`), from the researchers' repo.
- Cohort: 7,982 unique split-assigned TCGA patients; each has a report.
- Backbone: `BioMistral/BioMistral-7B`, loaded in **4-bit NF4** with
  double quantization and FP16 compute, `transformers`.
- Embedding: final-token hidden representation, L2 normalized, stored as one
  4,096-element float32 vector per report.
- Output: `embeddings/report/<TCGA-case-id>/<original-report-filename>.npy`.
- All 7,982 files passed shape, finiteness, unit-norm and exact filename/patient
  alignment audits. The team's full PyHealth pipeline generated 7,982 report-only
  survival samples (2,192 observed deaths, 5,790 censored).
- Report-only CoxPH C-index on five paper folds: **0.7501 ± 0.0100**
  (folds: 0.742721, 0.747255, 0.742931, 0.750375, 0.767042). This is an
  *observed project result*, not a guarantee of exact paper reproduction.
- **Critical methodology difference:** 4-bit Transformers inference is **not**
  guaranteed numerically identical to the authors' BF16/vLLM embedding setup.
  The script is a documented project adaptation, not a replacement for their
  reference script when exact numerical reproduction is required.

## Commands

Requires Python, `numpy`, `pandas`, and (for inference only) a CUDA-enabled
PyTorch installation, `transformers`, `accelerate`, and `bitsandbytes`.
A Tesla T4 was used for the full run; do not assume the model will fit on CPU.

Run from the root of this *data-preparation project* (substitute your paths):

```bash
# CPU-only: audit already generated vectors; no model downloads
python data/scripts/embed_reports_biomistral.py \
  --reports /path/to/multimodal-cancer-modeling/data/summarized_reports.csv \
  --splits /path/to/multimodal-cancer-modeling/results/split_cases.csv \
  --output-dir /path/to/tcga_data/embeddings/report --check-only

# GPU-only: generate up to five NEW vectors; rerun to resume
python data/scripts/embed_reports_biomistral.py \
  --reports /path/to/multimodal-cancer-modeling/data/summarized_reports.csv \
  --splits /path/to/multimodal-cancer-modeling/results/split_cases.csv \
  --output-dir /private/path/embeddings/report --max-new 5

# CPU-only unit tests (synthetic data)
python -m pytest data/tests/test_embed_reports_biomistral.py -q
```

The generator validates existing outputs before skipping them. It writes each
vector via a temporary file and then renames it, and rejects non-finite values,
unexpected embedding dimensions, and reports longer than 2,048 tokens rather
than silently truncating them. `embedding_config.json` contains source-file
hashes and important inference settings; a new run refuses to mix known
incompatible configurations in the same output folder. When using older
embeddings generated by notebooks, confirm compatible provenance first.

### Source code vs. data

Do not commit `tcga_data/`, `*.h5`, `*.npy`, `*.npz`, `*.tar.gz`, model caches,
Hugging Face tokens, clinical patient tables or patient-level manifests to a
public repository. Treat gated UNI2-h features and their derived representations
as subject to the source's access/redistribution terms. Commit scripts,
CPU-only synthetic tests, this README, and *aggregate* benchmark metrics only.

## UNI2-h histology aggregation (pilot validated)

The source is the *gated* `MahmoodLab/UNI2-h-features` dataset on Hugging Face.
Each TCGA project archive contains one HDF5 file per histology slide, with
`features` shaped `(1, patches, 1536)` and `coords` (not used). The original
authors' `embed_hist_uni2.py` computes a **simple mean of patch features** for
each slide and keeps separate vectors for multiple slides from one patient.
Our CPU-only script implements that pooling with float64 chunked sums before
saving a 1536-element float32 `.npy` vector. Results may have tiny rounding
differences from an all-at-once float32 NumPy mean. **Do not L2-normalize**
these slide vectors; report-embedding normalization is a different method.

The DLBC pilot generated 43 validated slides from 44 archive members, covering
43 distinct fold-assigned patients. PyHealth produced 43 survival samples,
7 observed deaths and 36 censored. These numbers describe **only DLBC**; other
TCGA histology projects have not been completed by this starter package.

```bash
# Process one local archive, safely, one slide at a time. Does not copy gated
# features into the PR and does not require model inference.
python data/scripts/aggregate_uni2_histology.py \
  --archive /private/TCGA-DLBC.tar.gz \
  --splits /private/split_cases.csv \
  --out-root /private/tcga_data --max-new 5

# Resume to finish the archive: valid existing slide .npy files are skipped.
python data/scripts/aggregate_uni2_histology.py \
  --archive /private/TCGA-DLBC.tar.gz \
  --splits /private/split_cases.csv \
  --out-root /private/tcga_data

# Verify that every study slide in this archive was successfully saved.
python data/scripts/aggregate_uni2_histology.py \
  --archive /private/TCGA-DLBC.tar.gz \
  --splits /private/split_cases.csv \
  --out-root /private/tcga_data --check-only

# The original authors' extracted slide folder works too.
python data/scripts/aggregate_uni2_histology.py \
  --source-dir /private/extracted_TCGA/ \
  --splits /private/split_cases.csv \
  --out-root /private/tcga_data

# CPU-only synthetic tests; no restricted features or model weights needed.
python -m pytest data/tests/ -q
```

Outputs follow `embeddings/histology/<patient_id>/<slide_filename>.npy`,
exactly as the PyHealth TCGA loader expects. The script rejects invalid input
shapes, missing patch features, non-finite numbers and unsafe archive paths;
it writes atomically and skips valid existing vectors on rerun. An archive-level
`--check-only` audits **that archive's matched slides**, not coverage of all
7,982 patients or all TCGA projects. If you add files to an existing PyHealth
root, delete the generated `tcga_multimodal_histology-pyhealth.csv` index (if
present) and use a fresh PyHealth cache to discover the new files.

**Data restrictions:** Each person obtaining gated UNI2-h features should
comply with their access terms. Do not publish archives, extracted tile vectors,
patient-level derived embeddings, credentials or private Drive copies in this PR.

## Multimodal alignment and numerical audit (PR Step 3)

`validate_tcga_data.py` is a **read-only CPU-only** validator for a PyHealth
`tcga_data` folder. It reads `clinical.csv`, `split_cases.csv` and any selected
`embeddings/<modality>/<case_id>/*.npy` directories. It verifies study/fold IDs,
vector dtype, dimension, finiteness, and report vector unit norm. Multiple
histology slides per patient are counted as **one covered patient**, though the
number of slide files is reported separately. It also reports overlap between
modalities, which is what matters for combined-model training.

```bash
# Works even when expression/ is not populated yet; it reports 0 coverage.
# Only the completed report modality is required to cover EVERY study patient.
python data/scripts/validate_tcga_data.py \
  --root /private/tcga_data \
  --modalities report histology expression \
  --require-complete report \
  --json-out /private/validation_results/multimodal_audit.json

# Optional: verify exact report filenames against the private handoff manifest.
python data/scripts/validate_tcga_data.py \
  --root /private/tcga_data \
  --modalities report histology expression \
  --require-complete report \
  --report-manifest /private/validation_results/report_embedding_manifest.csv
```

By default the validator expects 4,096-dimensional report vectors,
1,536-dimensional histology vectors, and 256-dimensional RNA-seq vectors.
Use `--expression-dim N` if the actual BulkRNABert checkpoint produces a
different verified dimension. An absent modality is shown as zero coverage,
**not** considered complete; list a modality under `--require-complete` only
when full study-cohort coverage is expected. A malformed file, a patient ID
absent from the clinical table, or a misnested `.npy` causes a failed audit.

The optional report manifest must have columns `case_id` and
`report_embedding_relpath`, with paths like
`embeddings/report/TCGA-AA-0001/TCGA-AA-0001.txt.npy`. It is patient-level
metadata; **do not commit it**. The `--json-out` summary contains only counts,
fold sizes and aggregate overlaps, not patient IDs or filenames. Do not
interpret a valid shape as evidence that an embedding came from the intended
model; provenance is tracked separately in `embedding_config.json`.

**Verified project state:** 7,982 valid report patients; 43 DLBC histology
patients; no expression embeddings yet in the checked Colab data folder. For
these inputs, expected overlap between report and histology is 43; the
three-way overlap is zero until RNA-seq embeddings are integrated. The
validator does not run PyHealth or fit a model; those integration tests were
performed separately and documented above.

The fold-level, aggregate report benchmark is in
`data/results/report_only_5fold.csv`. It is not a patient-level prediction file.

## Grouped HDF5 vector conversion (PR Step 4)

`convert_h5_embeddings.py` converts **already-pooled** HDF5 vectors (e.g.,
`expr.h5` or the original research pipeline's `hist.h5`) to patient-level `.npy`
files readable by the team's PyHealth dataset loader. Input groups must be
`<case_id>/<source_filename>`, with each HDF5 dataset a nonempty **1-D vector**.
It does **not** create embeddings from RNA counts, does **not** pool UNI2-h
raw patch arrays, and does **not** infer a patient ID from a slide image. Use
`aggregate_uni2_histology.py` for the original gated UNI2-h tile archive.

```bash
# Convert a vetted grouped expression HDF5 file, keeping only split-assigned
# patients from split_cases.csv. clinical.csv must also be present in root.
python data/scripts/convert_h5_embeddings.py \
  --h5 /private/expr.h5 --modality expression \
  --out-root /private/tcga_data --study-only

# Audit every expected output vector against its HDF5 source (no writes).
python data/scripts/convert_h5_embeddings.py \
  --h5 /private/expr.h5 --modality expression \
  --out-root /private/tcga_data --study-only --check-only

# Use an explicitly verified embedding dimension if the checkpoint differs
# from this project's default of 256 for expression:
#   --expected-dim N

python -m pytest -q data/tests/
```

The converter preserves source filenames by appending `.npy` and saves
`embeddings/<modality>/<case_id>/<source_filename>.npy`. It checks the TCGA
case-ID syntax, clinical-patient alignment, vector dimension, float32 cast
finiteness, and the **numerical contents** of already-existing files before
skipping them. It fails rather than silently mixing outputs that differ. Use
`--overwrite` only after confirming the source, model and preprocessing
provenance; `--check-only` reports missing and mismatched existing files without
writing anything. Saves use temporary files followed by atomic replacement.

**Do not run this converter on your completed quantized BioMistral report
folder using an HDF5 file from a different embedding configuration.** An
HDF5 source with different numerical content is not equivalent just because
it has 4,096 dimensions. The current study report vectors came from a distinct
4-bit NF4 inference process; preserve them and their `embedding_config.json`.

If future RNA-seq or histology source HDF5 files are obtained, inspect the HDF5
hierarchy and embedding dimensions *first*: do not assume the above hierarchy
fits raw per-sample gene-expression data or raw UNI2-h patch feature files.
The HDF5 converter's **synthetic tests** do not establish that an as-yet-
unavailable RNA-seq file can be converted without adjustments. The validated
real-data tests thus far are BioMistral 7,982 report files and the 43 DLBC
UNI2-h slide embeddings.
